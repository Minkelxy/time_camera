# 户外定时拍照系统 测试与验证方案

> 文档版本：v1.0
> 对应规格：`.trae/specs/build-outdoor-timed-camera/spec.md` → Requirement: 测试与验证
> 对应任务：Task 11（SubTask 11.1 / 11.2 / 11.3）
> 适用固件：`firmware/`（ESP-IDF v5.1，ESP32-S3）
> 适用硬件：见 `hardware/power_design.md`、`hardware/enclosure_design.md`、`hardware/gpio_allocation.md`

本文档汇总四类测试（功耗、室内功能联调、户外长期、固件烧录/单元测试），并附带测试报告模板与问题追踪表。所有指标来源于 `power_design.md` 功耗预算与 `spec.md` 验收要求，可在沙箱无硬件环境下直接作为执行手册。

## 一、功耗测试方案

### 1.1 测试目的

验证系统满足 `spec.md` 与 `power_design.md` 中规定的低功耗指标：

- 深度睡眠电流 **< 1 mA**（设计目标 ~0.5 mA）
- 拍照瞬间峰值电流 **< 300 mA**（设计目标 ~250 mA 平均，~350 mA 瞬时峰值由 470µF 电容吸收）
- 平均日能耗符合太阳能 + LiFePO4 电池供电预算（设计值 0.095~0.20 Wh/天）

### 1.2 测试设备

| 设备 | 用途 | 推荐型号 / 规格 |
|------|------|----------------|
| 数字万用表（µA / mA 档） | 测量深度睡眠静态电流 | 4½ 位以上，µA 档分辨率 ≤ 0.1µA，如 UT61E、Fluke 117 |
| USB 电流监测仪 | 测量工作期间平均电流 | Power-Z KT002 / FNIRSI FNB48，支持 mAh 累计 |
| 可调直流电源 | 替代电池供电，模拟不同电压 | 0~5V 可调，限流 ≥ 500mA，如 DP30V3A |
| 示波器（可选） | 捕捉唤醒-拍照瞬间电流波形 | 带宽 ≥ 50MHz，配电流探头或 0.1Ω 采样电阻 |
| 0.1Ω 精密采样电阻（可选） | 示波器测电流的串联电阻 | 1% 1W，串联在 3.3V 链路 |
| 鳄鱼夹 / 杜邦线 | 串联万用表到 3.3V 链路 | — |

### 1.3 测试方法

#### 1.3.1 深度睡眠电流

1. **断开太阳能板与电池**，仅 USB 或可调电源供电（3.3V 直接注入或经 LDO 输入端 3.2V）。
2. 万用表切换至 µA 档，串联在 HT7333 LDO 输出（3.3V 主电源）到系统负载的链路中。
3. 通过串口命令或上电后等待一个业务周期完成，触发 `power_enter_deep_sleep(0, GPIO_NUM_21)`。
4. **等待 30 秒**，确保 WiFi 射频完全关闭、外设 MOSFET 关断，读取稳定电流值。
5. 重复测 3 次取平均。

#### 1.3.2 唤醒瞬间峰值电流

1. 示波器电流探头卡在 3.3V 主回路，或用 0.1Ω 电阻 + 示波器电压通道测量压降换算电流。
2. 触发 DS3231 闹钟唤醒，示波器单次触发捕捉从唤醒到拍照完成（约 6~7s）的完整电流波形。
3. 测量波形最高点峰值电流，记录持续时长。

#### 1.3.3 拍照工作电流（平均）

1. USB 电流监测仪串联在供电回路，复位统计。
2. 配置 `interval_minutes = 1`，连续触发 3 次拍照周期。
3. 监测仪记录每个周期（从唤醒到进入深睡）的平均电流与持续时间。
4. 取 3 次平均电流与时长均值。

#### 1.3.4 WiFi 回传电流（如配置开启）

1. `config.json` 中设置 `upload_enabled=true`、`wifi_ssid`/`wifi_password`/`server_url`，本地起一个 HTTP 服务器（如 `python3 -m http.server` 或 `nc -l 8080`）接收上传。
2. 监测仪记录从 WiFi 连接开始到上传完成关闭 WiFi 的完整电流波形与平均电流、时长。

### 1.4 预期指标表

基于 `power_design.md` 第 8.1 节（状态电流明细）：

| 状态 | 电流 | 时长/次 | 频次/天 | 日均耗电（mAh，3.2V） |
|------|------|---------|---------|----------------------|
| 深度睡眠 | < 0.5 mA | — | ~23.9 h | ~12 |
| 唤醒 + 初始化 | ~80 mA | 1 s | 48 | ~1.07 |
| 拍照（含 ESP32+OV2640） | ~250 mA | 2 s | 48 | ~6.7 |
| SD 写入 | ~100 mA（与拍照重叠，已含在 250mA 中） | 0.5 s | 48 | — |
| WiFi 回传（可选） | ~170 mA | 10 s | 24（50% 照片） | ~11.3 |
| **每日合计（无 WiFi，5min 间隔 288 次）** | — | — | 288 | ~99 |
| **每日合计（含 WiFi，30min 间隔 48 次）** | — | — | 48 | ~30 |

> 说明：
> - 5min 间隔场景对应室内高频测试，30min 间隔对应户外实际部署。
> - `power_design.md` 给出的设计日均能耗为 0.095 Wh（无 WiFi）/ 0.131 Wh（含 WiFi），即 29.8 / 41.1 mAh，与上表量级一致。
> - 深度睡眠电流构成（共 ~500µA）：ESP32-S3 深睡 230µA + DS3231 200µA + 分压网络 16.5µA + LDO Iq 4µA + 上拉漏电 50µA。

### 1.5 通过判据

| 项 | 判据 |
|----|------|
| 深度睡眠电流 | 实测 **< 1 mA**（目标 ~0.5 mA） |
| 拍照峰值电流 | 实测 **< 300 mA**（瞬时尖峰 ≤ 350mA 由 470µF 电容吸收，<5ms） |
| 拍照平均电流 | 实测 ~250 mA ± 30mA |
| 日均耗电 | 实测 ≤ 预算的 1.5 倍（含 50% 安全余量），即无 WiFi < 0.14 Wh/天，含 WiFi < 0.20 Wh/天 |
| 太阳能充电电流（晴天） | > 800 mA（5W 板，Imp=1.0A） |

## 二、室内功能联调方案

### 2.1 测试环境

- 桌面 + USB 供电（5V）+ 可调电源模拟电池电压
- ESP32-S3 模组裸板 + OV2640 摄像头模组 + DS3231 RTC + MicroSD 卡（FAT32，≥ 4GB）
- 串口工具（115200 8N1，GPIO43/44）
- 本地 HTTP 服务器（用于 WiFi 回传验证）

### 2.2 测试项目清单

下表 12 项测试每项独立执行，记录结果于"记录表"。所有测试要求无 `panic`、无异常复位（除深度睡眠唤醒复位外）。

| # | 测试项 | 步骤 | 预期 | 记录 |
|---|--------|------|------|------|
| 1 | RTC 时间读写 | 串口下发命令设置 DS3231 时间（如 `set 2026-08-03 14:30:00`），断电重启读取 | 重启后时间保持一致，偏差 < 1s | ☐ 通过 ☐ 失败 |
| 2 | RTC 闹钟唤醒 | 设置 2 分钟间隔闹钟，万用表监测 3.3V 链路电流 | 2 分钟后电流从 ~0.5mA 跃升至 ~80mA（唤醒），日志记录"Alarm2 已设置" | ☐ 通过 ☐ 失败 |
| 3 | 摄像头拍照 | 每次唤醒拍 1 张，检查 SD 卡 `/sdcard/photos/` 下 JPEG 文件 | 文件存在，可被图像查看器打开，分辨率匹配 `config.resolution` | ☐ 通过 ☐ 失败 |
| 4 | SD 卡存储命名 | 检查目录与文件命名 | 目录 `/sdcard/photos/YYYYMMDD/`，文件 `HHMMSS.jpg`，文件大小 > 10KB | ☐ 通过 ☐ 失败 |
| 5 | 配置加载 | 修改 `config.json` 不同字段（interval/resolution/quality/upload_enabled），重启 | `config_mgr` 日志打印新值，行为匹配 | ☐ 通过 ☐ 失败 |
| 6 | 日志记录 | 检查 `/sdcard/logs/YYYYMMDD.log` | 格式 `[YYYY-MM-DD HH:MM:SS] [LEVEL] [event] msg`，时间戳来自 RTC | ☐ 通过 ☐ 失败 |
| 7 | 日志滚动 | 单文件 > 1MB 时触发滚动（可写脚本快速写日志） | 自动重命名为 `YYYYMMDD_1.log`，新建 `YYYYMMDD.log` 继续 | ☐ 通过 ☐ 失败 |
| 8 | 容量管理 | 填充 SD 卡到剩余空间 < 10%，触发下次拍照周期 | `cleanup_sd_if_needed()` 删除最早日期目录，日志记录 `cleanup` 事件 | ☐ 通过 ☐ 失败 |
| 9 | 电池电量采样 | 可调电源模拟 3.65V / 3.2V / 3.0V，读取 ADC | `power_get_battery_percent` 返回 100% / ~50% / ~10%（误差 ±5%） | ☐ 通过 ☐ 失败 |
| 10 | 低电量保护 | 模拟 3.0V 电压（处于 3.0~3.2V 区间） | 拍照间隔翻倍（48→24 次/天 或 config 间隔 ×2），日志 WARN | ☐ 通过 ☐ 失败 |
| 10b | 低电量停拍 | 模拟 < 3.0V 电压 | `power_should_skip_capture` 返回 true，跳过拍照直接进睡眠，日志 WARN | ☐ 通过 ☐ 失败 |
| 11 | WiFi 回传 | `upload_enabled=true`，本地 HTTP 服务器接收上传 | 照片完整上传（字节数一致），上传后 WiFi 关闭，日志 INFO `upload ok` | ☐ 通过 ☐ 失败 |
| 11b | 上传重试 | 关闭本地服务器，触发上传失败 | 重试 2 次后跳过，照片保留本地，日志 ERROR `upload failed after 2 retries` | ☐ 通过 ☐ 失败 |
| 12 | 配置门户 | 长按 GPIO0 ≥ 5 秒，手机连接 SoftAP `OutdoorCam-XXXX` | 密码 `12345678`，浏览器访问 `http://192.168.4.1/` 看到表单 | ☐ 通过 ☐ 失败 |
| 12b | 配置提交 | 在表单修改字段并提交 | 返回保存成功页，3 秒后重启，重启后 `config.json` 生效 | ☐ 通过 ☐ 失败 |
| 13 | 错误恢复 - 摄像头 | 故意拔掉摄像头排线 | 重试 3 次（CAM_INIT_RETRY_COUNT=3），每次重新上下电，失败后进睡眠 | ☐ 通过 ☐ 失败 |
| 14 | 错误恢复 - SD 卡 | 故意拔掉 SD 卡 | SD 初始化重试 2 次（SD_INIT_RETRY_COUNT=2），失败后 abort_cycle_and_sleep | ☐ 通过 ☐ 失败 |
| 15 | 错误恢复 - 写入失败 | SD 卡写保护或满 | 写入重试 3 次（WRITE_RETRY_COUNT=3），失败仍释放帧缓冲、关摄像头 | ☐ 通过 ☐ 失败 |

> 表中 #1~#12 为规格要求的核心 12 项；#10b / #11b / #12b / #13~#15 为错误路径补充测试，用于覆盖 `app.c` 中的重试与兜底逻辑。

## 三、户外长期测试方案

### 3.1 测试环境

- 实际户外安装（阳台 / 楼顶 / 野外），完整硬件：ESP32-S3 主板 + 摄像头 + DS3231 + MicroSD + LiFePO4 电池 + 5W 太阳能板 + IP65 外壳
- 安装方式参考 `enclosure_design.md`（抱箍 / 壁挂 / 三脚架），太阳能板朝南倾斜约等于当地纬度
- 串口通过 USB 延长线引出（便于现场取日志），或通过 SD 卡读卡事后分析

### 3.2 测试周期

**连续运行 ≥ 7 天**（对应 `spec.md` Scenario: 户外长期测试）。

### 3.3 测试前准备

| 准备项 | 操作 |
|--------|------|
| 电池充满 | 充至 ≥ 3.4V（CN3791 STAT2 绿灯亮） |
| 固件烧录 | 烧录最新固件（见第四章），串口确认 `app_main` 正常启动 |
| SD 卡 | 格式化为 FAT32，写入 `config.json`：`interval_minutes=30`、`upload_enabled=false`、`resolution=1600x1200`、`quality=10` |
| 时间校准 | 通过串口或配置门户设置 DS3231 时间为当前北京时间 |
| 初始状态记录 | 记录时间、电池电压（`/status` 接口或日志）、SD 卡剩余空间 |
| 安装 | 按选址建议安装，确保太阳能板 9:00~15:00 无遮挡，摄像头朝向目标 |
| 防潮检查 | 确认密封圈压紧、PG7 接头拧紧、干燥剂已放置 |

### 3.4 监测指标

每日检查（或事后从 SD 卡日志分析）：

| 指标 | 检查方法 | 期望 |
|------|----------|------|
| 拍照数量 | 统计 `/sdcard/photos/YYYYMMDD/` 下文件数 | 30min 间隔 → 48 张/天；偏差 ≤ 1 张 |
| 拍照质量 | 随机抽 5 张在电脑查看 | 清晰、曝光正常、无花屏、文件大小 > 10KB |
| SD 卡剩余空间 | 通过 `/status` 接口或读卡器 | 剩余 > 10%，触发清理后回升 |
| 电池电压曲线 | 日志 `boot` 事件中 `Vbat` 字段，或 `/status` | 始终 > 3.0V，晴天回升至 3.3~3.4V |
| 重启次数 | 日志中 `Boot` / `业务周期开始` 计数 | 仅深度睡眠唤醒复位，无异常复位 |
| 错误日志 | `grep ERROR /sdcard/logs/*.log` | 无持续 ERROR；偶发 ERROR（如单次上传失败）可接受 |
| 温度 | DS3231 温度寄存器（`ds3231_get_temperature`） | 记录日最高/最低，作为环境温度参考 |
| 太阳能充电状态 | CN3791 STAT1/STAT2 LED，或日志中电压日间回升 | 白天电压上升，夜间下降 |

### 3.6 通过判据

| 项 | 判据 |
|----|------|
| 拍照成功率 | 7 天内 ≥ **95%**（48 张/天 × 7 天 = 336 张，失败 ≤ 17 张） |
| 电池电压 | 始终 > **3.0V**（有太阳能补充应稳定在 3.3~3.4V） |
| 异常重启 | 无（除深度睡眠唤醒复位外，不应有 POWERON_UNDEFINED 复位） |
| 错误日志 | 无持续 ERROR；同一 ERROR 不连续出现超过 3 次 |
| SD 卡空间 | 自动清理机制生效，剩余空间始终 > 10% |
| 外壳防护 | 测试结束后开盖检查，内部无水珠、无粉尘侵入（IP65 验证） |

## 四、固件烧录与单元测试流程

### 4.1 烧录流程

| 步骤 | 命令 / 操作 | 说明 |
|------|-------------|------|
| 1 | 安装 ESP-IDF v5.1 + 工具链 | 参考 `firmware/README.md`，需含 Python 3.8+、CMake、Ninja |
| 2 | `cd firmware && idf.py set-target esp32s3` | 设置目标芯片 |
| 3 | `idf.py build` | 编译固件，生成 `build/firmware.bin` 等 |
| 4 | USB 连接 ESP32-S3，进入下载模式 | 按住 BOOT 按 RST，或依赖自动 RTS/DTR 时序 |
| 5 | `idf.py -p /dev/ttyUSB0 flash monitor` | 烧录并打开串口监视器（115200 8N1） |
| 6 | 首次配置 | 通过配置门户（长按 GPIO0 5 秒）或 SD 卡 `config.json` |

> Linux 下串口设备名通常为 `/dev/ttyUSB0`，Windows 为 `COMx`，macOS 为 `/dev/cu.usbserial-XXXX`。

### 4.2 单元测试（可选，ESP-IDF unity 框架）

在 `firmware/test/` 目录创建测试用例（如有时间），覆盖纯逻辑函数：

| 模块 | 函数 | 测试要点 |
|------|------|----------|
| `ds3231` | `bin2bcd` / `bcd2bin` | 0↔0x00、59↔0x59、99↔0x99 边界 |
| `ds3231` | 12/24 小时制解析 | bit6=1 时 PM/AM 转换（12pm=12, 12am=0） |
| `ds3231` | 闹钟跨日计算 | `now=23:50 + 30min` → `00:20` |
| `config_mgr` | JSON 解析 | 缺字段回退默认值、字段类型错误忽略、`interval` 越界（0/1441）处理 |
| `config_mgr` | 字符串截断 | ssid > 63 字节安全截断且 NUL 终止 |
| `power_mgmt` | `power_get_battery_percent` | 3.65→100%、3.4→100%、3.2→50%、3.0→10%、<3.0→0% |
| `power_mgmt` | `power_should_skip_capture` | <3.0V 跳过；3.0~3.2V 间隔翻倍（含 255 上限保护）；≥3.2V 不变 |
| `logger` | 日志滚动 | 模拟文件大小 > 1MB 触发 `_1.log` 重命名 |
| `config_portal` | `url_decode` / `form_get_value` | `%XX` 转义、`+`→空格、多字段分隔 |

测试运行：

```bash
cd firmware
idf.py create-test -c <component_name>   # 生成测试模板
idf.py -p /dev/ttyUSB0 flash monitor --test
```

### 4.3 回归测试

- 每次固件更新前跑一遍**第二章室内功能联调**
- 关键变更（电源管理、业务流程、存储）后跑一遍**第一章功耗测试**确认无回归
- 版本发布前完成**第三章 7 天户外测试**

## 六、问题追踪

测试中发现的问题按下表格式记录，统一编号管理：

| 编号 | 日期 | 现象 | 复现步骤 | 严重程度 | 状态 | 负责人 |
|------|------|------|----------|----------|------|--------|
| BUG-20260803-001 | 2026-08-03 | 深度睡眠电流 1.2mA，超出 1mA | 断电后等 30s 读取 | 高 | ☐ 待处理 ☐ 处理中 ☐ 已修复 ☐ 已验证 | |
| BUG-20260803-002 | 2026-08-03 | DS3231 闹钟唤醒后未拍照 | 设 2min 闹钟，唤醒后串口无拍照日志 | 高 | | |
| ... | | | | | | |

**严重程度分级**：

- **致命**：系统无法启动 / 持续 panic / 数据丢失
- **高**：核心功能失效（拍照/存储/唤醒失败），影响户外长期运行
- **中**：非核心功能失效（WiFi 回传失败但本地照片正常）、性能不达标
- **低**：日志格式、界面显示、文档问题

**状态流转**：待处理 → 处理中 → 已修复 → 已验证 → 关闭
